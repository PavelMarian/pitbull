# Конвенция отчётов об экспериментах

Каждый шаг `docs/PLAN.md`, у которого `done-when` содержит число или вердикт
(RQ0–RQ3, ярус C по остатку), при завершении кладёт сюда файл
`<id>-<slug>.md` (например `a2-rq0-olist.md`). Формат — тот же, что уже
использован в `pilot/REPORT.md`, просто оформленный по одному на эксперимент:

1. **Вопрос.** Что именно проверяем, одной фразой.
2. **Метод и команда воспроизведения.** Скрипт/параметры/сиды, достаточные
   чтобы прогнать заново.
3. **Предрегистрированное правило решения.** Порог из §8 плана или явно
   зафиксированный заранее критерий — сформулированный ДО того, как видны
   числа.
4. **Данные.** Сырые числа/таблица (или ссылка на неё, если объёмная).
5. **Вердикт.** Один из `positive | neutral | negative`.
6. **Вывод.** Что это меняет в плане/статье — в том числе если меняет мало
   или ничего.

Отрицательный или нейтральный вердикт — не повод не писать отчёт: пилотный
F0 = 1/12 (`pilot/REPORT.md`) уже показал, что именно такой результат может
переопределить главный тезис статьи. Шаг в `docs/PLAN.md` не помечается
`done`, пока соответствующий отчёт не закоммичен — включая случай, когда
результат неудобный.

Сырые артефакты прогонов (полные json/csv) в git не обязательны, если они
уже лежат в `prestudy/`, `pilot/` или `rel/` рядом с кодом — отчёт может на
них ссылаться путём; сюда попадают только выжимка и текст.
